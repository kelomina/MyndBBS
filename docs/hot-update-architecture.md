# MyndBBS 热更新架构

## 目标

将高频变化的前端发布物和非核心后端业务插件与稳定核心解耦，同时保留签名校验、健康检查、原子切换和回滚能力。

## 边界

- **前端发布层**：每个版本放入独立 `releases/<version>` 目录，通过 `current` 原子链接切换；SSR 进程采用蓝绿启动，旧进程健康期间继续承接流量。
- **后端核心层**：认证、权限、Prisma、迁移、上传安全和 Express 基础设施仍采用不可变镜像，并执行滚动更新。
- **后端插件层**：插件是独立进程，通过受限 HTTP/RPC 契约注册路由和查询；插件包必须带 manifest、版本和 SHA-256，加载失败自动保留旧版本。
- **运行时配置**：仅允许白名单配置进入数据库/Redis 热更新，禁止配置执行任意代码。

## 发布协议

1. 上传版本包到临时目录。
2. 校验 manifest、SHA-256 和签名。
3. 在隔离端口启动新版本。
4. 检查 `/api/health`、关键前端路由和插件探针。
5. 原子切换反向代理 upstream 或 `current` 链接。
6. 观察窗口内无错误后删除旧版本；失败则切回旧版本。

数据库迁移属于核心变更，禁止通过插件热更新执行；必须先备份，再随核心滚动发布。
